# TASK_T2_STEPPER_DRIVER — AeroStand: драйвер шаговых двигателей и командный протокол

## Контекст

T1 закрыт (496659d). Проект собирается, USB CDC инициализирован, GPIO трёх осей назначены:
- Ось 0: STEP0=PB4 (TIM3_CH1), DIR0=PD2, EN0=PD4
- Ось 1: STEP1=PB7 (TIM4_CH2), DIR1=PD5, EN1=PD7
- Ось 2: STEP2=PE5 (TIM9_CH1), DIR2=PG2, EN2=PG3

Драйверы MP8825: интерфейс STEP/DIR/EN, активный уровень EN — LOW (enable).
Моторы NEMA17 (17HS08-1004S), 1.0A, 200 шагов/оборот.

## Что сделать

### 1. Модуль stepper (Core/Src/stepper.c, Core/Inc/stepper.h)

Реализовать драйвер для управления шаговым двигателем через STEP/DIR/EN:

- `stepper_init()` — инициализация всех трёх осей (EN=HIGH → драйвер выключен)
- `stepper_enable(axis)` / `stepper_disable(axis)` — EN=LOW/HIGH
- `stepper_move(axis, steps, dir, freq_hz)` — запустить движение: генерировать `steps` импульсов на STEP с частотой `freq_hz`, направление по `dir` (0/1 на DIR-пине)
- `stepper_is_busy(axis)` — возвращает 1, пока ось движется
- `stepper_stop(axis)` — аварийная остановка оси (прекращение импульсов)

Генерация STEP-импульсов — по прерыванию таймера (Output Compare или простой период + счётчик шагов в ISR). Каждый фронт STEP — один шаг.

Допустимый диапазон freq_hz: 1–5000 Гц. При 5000 Гц и 200 шагов/оборот = 25 об/с = 1500 об/мин — это потолок для NEMA17 без микрошага.

### 2. Командный протокол по USB CDC

Текстовый протокол, строки завершаются `\n`. Парсер в `cmd_parser.c` / `cmd_parser.h`.

Команды (от ПК → МК):

| Команда | Формат | Описание |
|---------|--------|----------|
| MOVE | `MOVE <axis> <steps> <dir> <freq>` | Запустить движение. axis=0,1,2; steps>0; dir=0/1; freq=1..5000 |
| STOP | `STOP <axis>` | Аварийная остановка оси |
| ENABLE | `ENABLE <axis>` | Включить драйвер оси |
| DISABLE | `DISABLE <axis>` | Выключить драйвер оси |
| STATUS | `STATUS` | Запросить состояние всех осей |
| PING | `PING` | Проверка связи |

Ответы (МК → ПК):

| Ответ | Формат | Когда |
|-------|--------|-------|
| OK | `OK\n` | Команда принята и выполнена/запущена |
| DONE | `DONE <axis>\n` | Движение оси завершено (все шаги отработаны) |
| ERR | `ERR <текст>\n` | Ошибка парсинга или невалидные параметры |
| STATUS | `STATUS <axis> <enabled> <busy> <pos>\n` ×3 | Состояние каждой оси: enabled=0/1, busy=0/1, pos=текущая позиция в шагах (от 0) |
| PONG | `PONG\n` | Ответ на PING |

Позиция (`pos`) — знаковый счётчик шагов, накапливается: dir=1 прибавляет, dir=0 убавляет. Сбрасывается при включении.

### 3. Интеграция в main.c

- В `while(1)`: проверка буфера USB CDC на наличие принятой строки → вызов парсера
- Приём через CDC_Receive_HS callback → кольцевой буфер → разбор по `\n`

## Чего НЕ делать

- Не трогать LCD — это позже
- Не делать микрошаг (M0/M1/M2) — сейчас полный шаг
- Не делать плавный разгон/торможение (acceleration ramp) — это T3

## Проверка (без железа)

- Проект собирается без ошибок и warnings
- Парсер корректно разбирает все команды (можно добавить юнит-тест или просто убедиться по коду)
- ISR считает шаги и останавливает таймер после нужного количества
